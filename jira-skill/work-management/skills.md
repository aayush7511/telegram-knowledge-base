## Core Concepts

**Work Items** are "units used to track bugs and individual pieces of work that must be completed."

**Workflows** are "the path your work items take from creation to completion."

**Boards** visualize workflow progression with columns representing statuses.

## Typical Daily Operations

1. **Create work items** - Add stories, tasks, or bugs
2. **Manage workflow** - Transition items through statuses
3. **Coordinate on boards** - Visual progress tracking
4. **Add comments** - Document decisions and progress
5. **Link issues** - Show dependencies and relationships

## Work Item Types Quick Reference

| Type | Purpose | Hierarchy | Example |
|------|---------|-----------|---------|
| Epic | Large initiative | Top level | "Launch authentication system" |
| Story | User requirement | Middle | "Reset forgotten password" |
| Task | General work | Middle | "Update dependencies" |
| Bug | Problem/defect | Middle | "Login fails on mobile" |
| Sub-task | Detailed activity | Detailed | "Write password reset email template" |

## Key Workflow Concepts

**Status**: Where item is (To Do, In Progress, Done)  
**Transition**: Action moving between statuses (Start Work, Complete)  
**Resolution**: Final state reason (Fixed, Won't Do, Duplicate)
